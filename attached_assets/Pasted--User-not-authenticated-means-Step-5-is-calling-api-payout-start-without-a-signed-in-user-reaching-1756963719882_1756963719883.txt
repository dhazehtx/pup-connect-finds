“User not authenticated” means Step 5 is calling /api/payout/start without a signed-in user reaching the route. That happens a lot in Replit’s embedded preview (cookies don’t always flow to the API).

Here’s a reliable fix—pick either A or B (A is easiest).

A) Quick fix: pass the Supabase session token from the client

Client (Step 5)

import { createClientComponentClient } from "@supabase/auth-helpers-nextjs";

const supabase = createClientComponentClient();

const connectStripe = async () => {
  setLoading(true);
  try {
    // make sure user is signed in
    const { data: { session } } = await supabase.auth.getSession();
    if (!session?.access_token) {
      alert("Please sign in to continue.");
      return;
    }

    // you should already have providerId & applicationId by now
    const res = await fetch("/api/payout/start", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        // ⬇️ send the JWT so the API can authenticate you even inside the Replit iframe
        Authorization: `Bearer ${session.access_token}`,
      },
      body: JSON.stringify({ providerId, applicationId, accountType }),
    });

    const data = await res.json();
    if (!res.ok || !data?.success || !data?.url) throw new Error(data?.message || "Setup failed.");
    window.location.href = data.url;
  } catch (e:any) {
    alert(e?.message || "Setup failed.");
    console.error(e);
  } finally {
    setLoading(false);
  }
};

This avoids cookie issues by authenticating with the Bearer token.

B) Alternative (cookie-based): read auth from cookies in the route

If you prefer not to pass the token, use the Next App Router helper and cookies (works best outside iframes):

import { cookies } from "next/headers";
import { createRouteHandlerClient } from "@supabase/auth-helpers-nextjs";

export async function POST(req: NextRequest) {
  const sb = createRouteHandlerClient({ cookies });
  const { data: { user } } = await sb.auth.getUser();
  if (!user) return NextResponse.json({ success:false, message:"User not authenticated" }, { status:401 });
  const userId = user.id;

If you use this cookie-based method in Replit’s embedded preview and still see 401, open the app in a new window/tab (so third-party cookie rules don’t block the auth cookie).

Also add a small client guard

Before calling the API, fail fast if the user isn’t logged in:

const { data: { user } } = await supabase.auth.getUser();
if (!user) {
  // redirect to sign-in or show modal
  router.push("/auth/signin?next=/services/onboarding/payout");
  return;
}

Why you saw that toast

Your server returned 401 because it couldn’t find an authenticated user (iframe blocked cookies), and your client shows the “Setup Failed – User not authenticated” message.

Apply A (token header) or B (cookie auth with new window) and you’ll be redirected to Stripe Connect on click.
