Why the shield still isn’t showing
Your database row does have is_admin = true, but the React code that loads the profile never asks Supabase for that column—so the context still looks like:

json
Copy
Edit
{
  "id": "...",
  "username": "Royalbabybullz",
  "user_type": "breeder",      // ← present
  "is_admin": null             // ← never selected, so stays null
}
Because is_admin is null, the header’s isAdmin check fails and the shield stays hidden.

1 Patch the profile-fetch hook to include is_admin
Open client/src/contexts/AuthContext.tsx (or whatever file contains your profile loader—sometimes useProfile.ts).

Find the Supabase query that runs right after sign-in:

ts
Copy
Edit
const { data } = await supabase
  .from("profiles")
  .select("id, username, full_name, avatar_url, user_type")   // ← current
  .eq("id", user.id)
  .single();
Add is_admin (and role if you like):

ts
Copy
Edit
.select("id, username, full_name, avatar_url, user_type, is_admin, role")
Save → Replit will rebuild.

No idea where the query lives?
Search the repo for .from("profiles").select – it’s usually in one of these files:

src/contexts/AuthContext.tsx

src/hooks/useUser.ts

src/utils/fetchProfile.ts

2 (If you use RLS) allow that column in your policy
If row-level security is enabled, make sure the SELECT policy is not using columns = (...) to whitelist only certain fields. Either:

sql
Copy
Edit
alter policy "Public read profiles"
  on profiles for select
  using ( true );                        -- everybody can read all columns
or add is_admin to the column list:

sql
Copy
Edit
with check ( true ) -- for insert/update
using ( true )      -- for select
3 Force the context to reload once
In the browser console run:

js
Copy
Edit
supabase.auth.refreshSession();   // triggers onAuthStateChange → profile refetch
—or simply log out / log back in one more time. This time the loader will include is_admin.

4 Shield logic stays as-is
Because the header code already says:

ts
Copy
Edit
const isAdmin =
  profile?.is_admin ||
  profile?.role === "admin" ||
  profile?.user_type === "admin";
…the icon appears as soon as profile.is_admin comes through.

Quick verification
Reload /explore

DevTools → Console: window.__debugProfile (or whatever variable you logged) now shows "is_admin": true

Shield icon (🛡️) renders next to the bell; click it → /admin

If the icon is still missing but the console shows "is_admin": true, inspect the DOM:

js
Copy
Edit
document.querySelector('a[href="/admin"]')
If it returns null → the isAdmin condition didn’t evaluate; double-check the header import path.

If it returns an element but it’s invisible, add class="text-red-500" temporarily to confirm it’s just CSS (e.g., overflow-hidden).

Do the select-column patch first; 90 % of the time that alone makes the shield pop right in. Let me know how it goes!
